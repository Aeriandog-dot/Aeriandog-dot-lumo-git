# Lumo — 网站信息库(可运行 MVP)

按第一性原理落地:把"原型"升级为 **真前后端 + 真持久化** 的可运行版本。
前端页面仍在 `public/`(无需构建工具),数据不再存在内存里,而是由后端服务统一读写。

## 快速开始
1. 确保已安装 Node.js(>=18)。
2. 在项目目录运行:
   ```
   node server.js
   ```
   或在项目目录用 `npm start`。
3. 浏览器打开:http://localhost:4780

> 演示登录:任意邮箱均可,验证码统一 **123456**。
> 数据自动从 `data/seed.json` 首次导入,之后持久化到 `data/db.json`。

## 管理后台(与用户端完全隔离)
- 独立页面: http://localhost:4780/admin.html(用户端不提供任何入口)
- 演示管理员: `admin@lumo.local`,验证码 `123456`
- 能力:查看待审核/已处理提交 → 填初始评分「通过收录」(自动进入对应分类)或「拒绝」(填原因)
- 所有后台接口均服务端鉴权:非管理员一律 403(见下方 API 表)
- 提交者在前台只看到三态进度:**正在审核 / 审核完成 · 已收录 / 未通过(+原因)**

## 已落地的能力(相对原型的关键升级)
- 数据由服务端提供:`GET /api/bootstrap`(分类/条目/运营状态/我的评分)
- 邮箱验证码登录 → 服务端会话(cookie,HttpOnly,30 天),**刷新/重开浏览器不掉线**
- 完整域名与官网链接:仅登录用户可见(未登录打码)
- 评分:**一账号一票**,服务端强制;改星只算一票;总量以服务端为准
- 提交收录:登录 → 提交 → 服务端存 `待审核`,用户只看"正在审核 / 审核完成"
- 最近浏览、DEAD 钢印、风险二次确认、风险网站"谨慎访问"等前端交互保留
- 前端只保留提交者进度,**前台无审核台**(审核是后端职责)

## 目录结构
```
lumo-app/
  server.js        # 零依赖 Node 服务(静态托管 + JSON API)
  package.json
  data/
    seed.json      # 初始数据(由原型 data.js 导出)
    db.json        # 运行期数据(自动生成)
  public/          # 前端(原生 SPA,由服务端托管)
    index.html / styles.css / app.js / boot.js / assets/
```

## API 一览(前后端同源)
| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| GET  | /api/bootstrap        | 全量初始数据 | 公开 |
| POST | /api/auth/send-code   | 发送验证码(演示固定 123456) | 公开 |
| POST | /api/auth/verify      | 验证并登录(下发会话 Cookie) | 公开 |
| GET  | /api/me               | 当前用户与我的评分/提交 | 公开(未登录返回空) |
| POST | /api/auth/logout      | 退出 | 会话 |
| POST | /api/items/:id/rate   | 评分(1–5,每账号一票) | 会话 |
| POST | /api/submissions      | 提交收录(进入待审核) | 会话 |
| GET  | /api/submissions/mine | 我的提交进度 | 会话 |
| GET  | /api/admin/subs        | 后台:提交队列 | 管理员 |
| GET  | /api/admin/stats       | 后台:统计     | 管理员 |
| POST | /api/admin/subs/:id/approve | 通过收录(写入初始评分) | 管理员 |
| POST | /api/admin/subs/:id/reject  | 拒绝(记录原因) | 管理员 |

## 上线前替换清单(生产化路线)
1. 存储:JSON 文件 → PostgreSQL(或托管数据库),加迁移与备份。
2. 验证码:固定 123456 → 真实邮件服务(存哈希+有效期+限频)。
3. 会话:内存 session → 服务端持久会话/JWT + 刷新令牌。
4. 管理:在前台之外单独建"后台服务 + 管理端"(独立域名、2FA、操作审计),
   审核通过后调用收录接口,前端提交者进度由该流程驱动。
5. 部署:源站放海外,前面套 Cloudflare(CDN+WAF),隐藏源站 IP;
   数据库/对象存储用托管服务;日志与告警接入。
6. 安全合规:收录自动存档快照(证据链)、申诉通道、服务条款/隐私政策,
   全程"风险提示 + 来源"表述、不替代官方定性。

## 前端说明
前端为原生 SPA(无构建依赖),由服务端直接托管;`boot.js` 同步拉取数据后 `app.js` 渲染。
改动前端后无需重新构建,刷新即可(生产可再上 CDN 缓存)。
## 运行配置(环境变量)
| 变量 | 默认 | 说明 |
|---|---|---|
| LUMO_PORT | 4780 | 服务端口 |
| LUMO_ADMIN | admin@lumo.local | 管理员邮箱(后台鉴权依据,不再写死) |
| LUMO_DEV_CODE | 123456 | 开发用验证码;正式环境应置空并接入真实邮件 |
| NODE_ENV | development | 生产环境建议设为 production(隐藏验证码提示) |
| LUMO_SMTP_HOST/PORT | 空 | SMTP 服务器(配置后验证码走真实邮件) |
| LUMO_SMTP_USER/PASS | 空 | SMTP 账号(465 隐式 TLS / 587 STARTTLS) |
| LUMO_SMTP_FROM | Lumo <no-reply@lumo.local> | 发件人 |
| LUMO_SMTP_SECURE | 自动(465=true) | 是否强制 TLS |\n| LUMO_DATA_DIR | 项目内 data/ | 数据目录(部署时指向持久磁盘,种子数据仍从代码仓库读取) |

> 验证码机制:随机 6 位 + SHA-256 存储 + 10 分钟有效 + 60 秒重发限制 + 5 次试错锁定。
> 未配置 SMTP 时(开发模式),验证码打印到服务端控制台并在登录提示中返回;配置 SMTP 后自动改为真实邮件。

Windows 可直接双击 `start.bat`;Linux/macOS:`LUMO_PORT=4780 LUMO_ADMIN=you@x.com node server.js`。

## 审核与打分原则(已固化为设计)
- **全部人工审核**,系统不做任何自动通过/拒绝/批量判定;
- 审核通过时必须由管理员**手动填写项目评分(0.5–10)**;缺少评分,后端拒绝上架;
- 人工填分并确认后,系统才**自动上架**到对应分类参与排序;
- 用户打分(1–5 星)由登录用户产生,一账号一票,系统只做统计。
